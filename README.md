# POSTEKS AI — локальная версия 2.0

Сервисный помощник ПОСТЭКС: клиентский чат, защищённая база знаний, Яндекс IMAP, обращения, очередь специалистов и проверенные решения. FastAPI + SQLAlchemy/Alembic + React/TypeScript. Отправка писем отключена.

Для действующей установки начните с [краткой инструкции по обновлению и проверке](docs/QUICK_START_RU.md).

## Запуск Windows

1. Распакуйте **весь** полученный Windows ZIP в отдельную папку, например `C:\POSTEKS_AI_2`. Нужен Python 3.11+. Интерфейс уже собран; Node.js требуется только при пересборке исходников.
2. Дважды нажмите `install.bat`. `.env` создаётся только при отсутствии; существующие настройки сохраняются.
3. Нажмите `start.bat`, создайте личного администратора при первом запуске.
4. Оставьте окно сервера открытым и нажмите `open-app.bat`. Сайт: `http://127.0.0.1:8080`, сотрудники: `/admin/knowledge`.
5. Дважды нажмите `check.bat`. При сбое приложите `support_report.json` из нового запуска. Подробные сценарии собраны в [TESTING_GUIDE_RU.md](TESTING_GUIDE_RU.md).

Для работы используется настоящий локальный backend. Прежний автономный HTML сохранён отдельно как материал предыдущей версии и не включён в новую поставку.

## Что исправлено

- **Почта:** TLS IMAP, проверка подключения, ручная и фоновая синхронизация, история порциями, входящие и отправленные, UID/UIDVALIDITY, дедупликация, цепочки по почтовым идентификаторам, журнал и закрытые вложения. Письма на сервере не перемещаются и не помечаются прочитанными.
- **Знания:** оригиналы, прогресс индексации, OCR, PDF-страницы, координаты таблиц и изображений, локальный поиск по модели. Для DOC/XLS нужен необязательный LibreOffice; отсутствие обработчика явно диагностируется.
- **Диалог:** сохраняются цель, этап, факты, просьба сотрудника и пожелания по встрече. Запрос специалиста создаёт одно обращение и поручение; ответ сотрудника возвращается в тот же чат. Выезд требует согласования.
- **Опыт:** TXT/JSON/CSV-переписки импортируются с предпросмотром и подтверждением только как внутренний непроверенный материал. Решения проверяются сотрудником отдельно, перед публикацией. Это накопление знаний, а не изменение весов модели.
- **Вложения:** закрытые фото/PDF/текст в чате; OCR и настраиваемый OpenAI vision для чтения маркировок. Голос преобразуется через официальный API, текст проверяется перед отправкой. Без ключа функции ИИ явно недоступны.
- **Контроль:** диагностика файла БД, папок, миграций, счётчиков, OCR и очередей; Playground с трассировкой и сохранённым контекстом. В журнале — request ID без содержимого писем и секретов.
- **Интерфейс:** читаемые размеры и контраст, обе темы, копирование ответов, исправление логотипа и нижней подписи. PWA требует поддерживаемого браузера и безопасного контекста.

## Данные и обновление

Пакет программы **не содержит вашу рабочую базу, письма, PDF/Excel и секреты**. Одна установка без переноса знаний будет пустой. Через админку загрузите PDF один раз либо положите исходники в `<STORAGE_DIR>/imports`:

```powershell
.\.venv\Scripts\python.exe -m scripts.manage import-sources
.\.venv\Scripts\python.exe -m scripts.manage diagnostics
```

Документы сначала внутренние: они доступны сотрудникам в Playground. Клиентский чат использует только материалы, отдельно разрешённые администратором. Внутренний документ «О компании» и сырые переписки не публикуйте.

Перед обновлением остановите приложение и выполните `python -m scripts.manage backup` через Python вашего venv. Установщик также резервирует существующую новую БД перед миграциями. Частные хранилища и `.env` не заменяются поставкой.

**Исходный `posteks.db` не подключается автоматически.** Его схема может отличаться. Доступны read-only аудит, снимок и явный импорт совместимых документов; см. руководство проверки. Не заменяйте им `storage/posteks_ai.db` и не применяйте к нему чужие миграции. Прежние `DB_URL`, `DATABASE_URL`, `SERVICE_STORAGE_ROOT` и относительные пути диагностируются.

## Яндекс и OpenAI

В локальном `.env` укажите `MAIL_IMAP_HOST=imap.yandex.com`, `MAIL_IMAP_PORT=993`, свой `MAIL_USERNAME` и пароль приложения `MAIL_APP_PASSWORD`. Доступ IMAP должен быть разрешён в Яндексе. Пароли и API-ключи не присылайте в чат.

Во «Входящих» выполните **Проверить подключение**, затем **Синхронизировать сейчас**. Историю импортируйте порциями. Папку отправленных система обнаруживает по флагу Sent либо использует `MAIL_SENT_FOLDER`. Диагностика показывает реально проверенное соединение и результаты. В `TEST` реальные подключения запрещены. `SAFE_MODE=true` и `MAIL_SEND_ENABLED=false` сохраняются; сервер не реализует SMTP-отправку даже после согласования черновика.

`OPENAI_API_KEY` задаётся только на сервере. Поддерживаются прежние `OPENAI_MAIN_MODEL`, `OPENAI_TRANSCRIPTION_MODEL`, `OPENAI_EMBED_MODEL`; доступность идентификаторов моделей проверяется через API. Без ключа работает ограниченный локальный режим с поиском, сохранением данных и передачей человеку, без имитации интеллектуальной диагностики.

[Перенос истории MAX](docs/MAX_IMPORT_RU.md): импорт текстового экспорта готов; возможность полного экспорта конкретного чата через официальный клиент необходимо подтвердить. Приложение само не получает доступ к вашему MAX.

## Разработка и проверки

```bash
bash scripts/install.sh
.venv/bin/python -m scripts.manage create-admin
bash scripts/start.sh
.venv/bin/python -m pytest -q
# В frontend:
npm ci
npm run build
# В корне, при установленных Playwright/Chromium:
.venv/bin/python -m scripts.browser_smoke
.venv/bin/python -m scripts.export_project
```

Браузерные проверки используют отдельные TEST-серверы и временные базы. Для проверки собственных PDF есть явный флаг `--with-private-sources`; результаты остаются в локальной `artifacts`. Каждая облачная задача уже изолирована, дополнительный Git worktree не требуется.

## Что требует вашей проверки

Windows, реальная Яндекс Почта и ответы вашего аккаунта OpenAI требуют локальной проверки с действующими настройками. Исходный `alembic.zip` и загруженный `posteks.db` превышают лимит передачи среды 32 МиБ и пока не прочитаны; содержимое прежней установки не считается автоматически объединённым.

Качество проверяйте на реальных вопросах с сотрудником. Доля вопросов, решённых без человека, определяется испытаниями. Таблицы нескольких модификаций, применимость деталей и опасные работы требуют проверки источника. Видеоанализ и нативные мобильные приложения в эту версию не входят.
