# Автоматическая проверка POSTEKS на вашем компьютере

После обновления **дважды щёлкните `check.bat`** в папке программы. Он проверит локальные файлы и базу, затем откроет отчёт в браузере. Окно `start.bat` можно оставить открытым.

Обычный запуск выполняется локально. Для OpenAI есть отдельный режим `-Live` с ограничением в **20 запросов на тестовых данных**. Он использует локальный ключ и расходует квоту. Для почты в обоих случаях проверяются только сохранённые записи и контрольные точки. Пробные загрузки, диалоги и импорты выполняются в отдельной временной базе.

## Как установить обновление

1. Остановите сервер через Ctrl+C и сохраните приватную резервную копию данных и `.env`, как описано в [инструкции обновления](../TESTING_GUIDE_RU.md#9-обновление-без-потери-данных-и-откат).
2. Распакуйте новый ZIP отдельно. Скопируйте программные файлы из `posteks_ai` в существующую папку программы с заменой, включая `check.bat`, `check.ps1`, `scripts`, `server` и `frontend`.
3. Сохраните прежние `.env`, рабочую БД, `storage`, `.venv` и резервные копии. Не заменяйте их новой пустой установкой. Запустите `install.bat`, затем `start.bat`.
4. Запустите `check.bat`. Убедитесь, что открыт новый отчёт с текущим временем, а не сохранённый старый.

## Что проверяется

| Проверка | Что означает результат |
|---|---|
| Модель напрямую и через приложение (`-Live`) | Один и тот же разговор из пяти реплик. Отдельно видны сбой провайдера и сбой обработки ответа приложением. |
| Контекст (`-Live`) | Модели передаётся новая реплика и история того же диалога. Проверяется сохранение названной модели оборудования и сообщения о выполненной проверке. |
| Файлы и знания | Проверяются наличие оригиналов, ошибки индекса, OCR, средства обработки видео и выборочные SHA-256. При локальной проверке один подходящий документ повторно загружается во временную базу и ищется через API. При отсутствии документа или в режиме `-Live` для пробной загрузки используется искусственный файл. |
| Ответ с источником (`-Live`) | Проверяется получение ответа модели и ссылки на найденный материал. |
| Вопрос об остановке привода (`-Live`) | Повторяется тестовый вопрос с описанием симптома. |
| Защитные проверки | Повреждённый PDF и пустой запрос должны быть отклонены; ожидаемая ошибка здесь означает успешный тест. Закрытый оригинал недоступен гостю. |
| Архив | Повторный импорт не создаёт дубликат. Старая просьба «пришлите счёт» не создаёт активную работу или отправку. |
| История почты | Показаны локальные записи, контрольные точки и пропуски. Подключение к Яндексу проверяется отдельно. |

`Пройдено`, `Ошибка`, `Требует внимания` и `Не проверено` — разные состояния. Пропущенный тест не засчитывается как успешный. Проверки передачи истории и наличия источника не заменяют оценку смысла всех ответов специалистом. При первом отказе разговорного теста приложения дальнейшие платные вопросы прекращаются.

Для проверки приложения с настоящей моделью выполните команду в PowerShell из папки программы.

```powershell
.\check.bat -Live
```

## Какой файл прислать для исправления

Каждый запуск сохраняется отдельно в `reports\selfcheck_<дата>_<время>_<идентификатор>`. Старые результаты сохраняются. Путь к последнему HTML записан в `reports\LATEST_REPORT.txt`.

- `REPORT.html` — читаемый отчёт; открывается автоматически.
- `SUMMARY.txt` — короткий текстовый результат.
- **`support_report.json` — файл для отправки мне.** Содержит ограниченную техническую диагностику без ключей, текстов писем, документов и ответов модели.
- **`PRIVATE_details.json` — только для вашего локального просмотра. Не отправляйте его.** Там могут быть настоящие ответы модели, сведения из внутренних материалов и пути файлов.

Не отправляйте целиком папку `reports`, `.env`, рабочую БД или архив почты. Проверка сама ничего не публикует и не пересылает.

## Почему HTTP 200 есть, а ответа нет

Ваш журнал показывает успешный запуск сайта и получение HTTP-ответа. Он не показывает, завершила ли OpenAI генерацию и приняло ли приложение результат. По прежней общей надписи на скриншоте точную причину установить нельзя.

Теперь записываются этап, безопасный код ошибки, тип исключения и идентификатор запроса. Проверка подключения использует тот же структурированный формат, что и рабочий чат, вместо короткого неструктурированного ответа. Предварительный запрос чтения метаданных модели больше не требуется для генерации.

| Код или этап | Что делать |
|---|---|
| `missing_openai_key`, `authentication_failed` | Проверить ключ в локальном `.env` и перезапустить приложение. Не присылать значение ключа. |
| `model_not_found`, `model_access_denied` | Сверить точное имя действующей модели в отчёте и доступ проекта OpenAI. Сохранённая настройка админки может отличаться от `.env`. |
| `insufficient_quota`, `provider_rate_limit` | Проверить квоту и лимиты проекта OpenAI. |
| `provider_connection_failed`, `provider_timeout` | Проверить соединение с OpenAI, прокси и сертификаты; повторить позже. |
| `response_output_limit` | Ответ оборвался до завершения JSON. Лимит теперь задаётся `MAX_AI_OUTPUT_TOKENS` в `.env`, по умолчанию 4096; допустимо 256–16384. Повышение расходует квоту и не исправляет другие ошибки. После изменения перезапустить приложение и повторить проверку. |
| `response_json_invalid`, `response_schema_invalid`, `citation_invalid`, этап `reply_validation` | Модель ответила, но приложение отклонило результат. Прислать `support_report.json`: это требует разбора конкретного формата или проверки доказательств. |

Ошибка модели не заменяется технической консультацией. Не нужно вручную повторять десятки вопросов: сначала достаточно нового отчёта. В облачной среде без ваших учётных данных настоящий OpenAI и Яндекс не проверены; эти результаты появятся только после запуска у вас. BAT и PowerShell также требуют проверки на вашей Windows.

## MAX и накопление знаний

Для существующей группы основной путь остаётся **без добавления бота**. Подтверждённой полной выгрузки обычной группы из официального клиента пока нет; это не доказательство отсутствия функции. Bot API описывает доступ бота и не даёт оснований обещать историю обычного пользователя или все сообщения до добавления бота.

Следующий практический шаг — установить платформу и версию вашего официального клиента MAX, роль в группе и проверить доступную выгрузку на **10–20 сообщениях с настоящими фото, видео и документами**. Если экспорта нет, сначала нужно проверить сохранение доступной истории и оригиналов через интерфейс этой версии; готовый сборщик всех лет пока не заявляется. Пароли, коды, cookies и токены сессии не нужны. Подробнее: [исследование MAX](MAX_INVESTIGATION_2026_11_09_RU.md) и [форматы импорта](MAX_IMPORT_RU.md).

При пилоте отдельно сверяются: полученные сообщения, авторы и время, идентификаторы и ответы, скачанные оригиналы, обработанное содержимое, доступность поиску и пропуски. Отсутствующие сведения отмечаются, а не восстанавливаются догадками. Повторная загрузка должна сохранять связи и не давать дублей. Полнота нескольких лет не выводится из успешного короткого фрагмента.

Бот накапливает **подтверждённые сотрудником решения**, связанные с исходной перепиской, моделью и ограничениями. Импорт архива сам по себе не подтверждает его технические утверждения и не обучает веса языковой модели. Старые цены, наличие, сроки, счета и собственные ответы ИИ не становятся автоматически актуальными знаниями. Руководства и разрешённые проверенные решения дополняют обычное понимание диалога моделью.
