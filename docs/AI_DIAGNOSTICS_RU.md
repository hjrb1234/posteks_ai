# Проверка диалога POSTEKS и сделанные исправления

**Обновление 12 ноября:** появился автоматический запуск `check.bat` с безопасным отчётом для поддержки. Проверка подключения теперь использует тот же структурированный ответ, что и чат. Этапы API, незавершённый ответ, JSON и проверка цитат различаются; по прежнему общему сообщению точная причина ошибки на Windows не установлена. Порядок запуска и границы проверки: [SELF_CHECK_RU.md](SELF_CHECK_RU.md).

Главное: причины шаблонов установлены по текущему коду и воспроизведены через приложение. Исправления внесены, но полный сценарий с настоящей языковой моделью здесь **ещё не подтверждён**: в облачной копии отсутствует ключ OpenAI. Дизайн и существующие рабочие данные сохранены.

## Что фактически настроено

В проверенной облачной копии основная, быстрая и vision-модель — `gpt-4.1-mini`, аудио — `gpt-4o-mini-transcribe`, embeddings — `text-embedding-3-small`. Ключ отсутствует; проверка подключения возвращает `configured=false`, `connected=false`, `provider_called=false`, `missing_openai_key`. Это настройки именно этой среды. Значения на вашем Windows могут отличаться и не заменяются при обновлении.

## Обнаруженные причины и доказательства

1. Новый текст отправлялся правильно. На последовательности из пяти вопросов журнал показывал пять разных текущих сообщений и историю длиной 0, 2, 4, 6 и 8 сообщений. Для воспроизведения повтора не понадобились ни кеш ответов, ни другой диалог.
2. Модель не вызывалась без ключа. Вместо неё включался `local_plan`, почти не использовавший историю. Реплики 2–5 получали дословно одинаковый ответ о шильдике.
3. Даже результат модели мог быть заменён сервером: технический ответ превращался в список цитат, организационный — в фиксированную фразу. Теперь связный текст действующей модели сохраняется; проверки источников и запрет невыполненных действий остаются.
4. Извлечение знаний пропускало склонения «ремень/ремни» и ошибочно считало номера сборочных чертежей моделями машин. В итоге страницы перечней деталей отбрасывались. Исправлены формы слов, область модели и проверка всех доступных текстовых страниц её руководства.
5. Закрытый оригинал ранее приходилось публиковать для клиентского ответа. Теперь администратор отдельно разрешает использование выдержек в ответах, сохраняя PDF, полные страницы и изображения закрытыми.
6. Предыдущие вложения не подгружались в следующий запрос, видео отвергались. Теперь сохраняются владелец, связь с репликой, оригинал и состояние обработки. Извлечённые кадры не называются просмотром всего видео или анализом звука.

## Один разговор до и после

Полные фактические реплики и признаки вызова модели: [dialogue_comparison.json](diagnostics/dialogue_comparison.json). Это проход приложения **без ключа**, не образец ответов настоящей модели.

| Сообщение | До исправления | После исправления без ключа |
| --- | --- | --- |
| Здравствуйте | Приветствие из локального сценария | Явное сообщение, что ключ не настроен и модель не вызывалась |
| У меня проблема с оборудованием | «Начнём с определения оборудования: пришлите фото шильдика…» | Ошибка модели, сообщение сохранено в том же диалоге |
| Какие сведения тебе нужны? | Дословно тот же текст о шильдике | Та же честно обозначенная недоступность модели |
| Объясни предыдущий ответ проще | Дословно тот же текст о шильдике | Ошибка не подменяется технической консультацией |
| Почему ты это спрашиваешь? | Дословно тот же текст о шильдике | История всех пяти реплик сохранена; выдуманного ответа и источника нет |

В отдельных тестах транспорт OpenAI заменён записывающей заглушкой. На этой же последовательности пять разных ответов заглушки прошли через приложение без замены; проверены точный новый текст, история, сохранение модели оборудования и выполненной проверки. Это доказывает исправление пути сообщения, **не качество действующей OpenAI-модели**. Прямое сравнение настоящей модели с приложением осталось невыполненным из-за отсутствия ключа.

## Сценарии и границы проверки

| Сценарий | Что проверено |
| --- | --- |
| Реальный PDF загружен и найден | Выполнено на отдельной временной БД через настоящие API загрузки и поиска. Оригиналы не изменялись. |
| Найденный материал передан модели, ответ с источником и уточнение | Полный путь HTTP → поиск → записывающая SDK-заглушка → ответ → следующая реплика проверен. Настоящая интеграция пока не выполнена. |
| Переформулированный вопрос | Проверены поиск и выбор страниц на реальных руководствах, а также синтетические регрессии. Правильность живого языкового ответа не подтверждена. |
| Только подтверждённый случай из переписки | Проверен через SDK-заглушку: используется VERIFIED-решение с ограничениями, исходная чужая переписка не передаётся. |
| Ответа нет | Предложенный заглушкой параметр без доказательства отклоняется; технический ответ не выдумывается сервером. |
| Модель, проверка и видео уже получены | Проверены память своей беседы и передача состояния файла в следующий запрос. Ошибка обработки обозначается отдельно. |
| Видео | FFmpeg/ffprobe и извлечение кадров проверены на настоящих сгенерированных MP4. Live vision не проверен; движение между кадрами и звук не объявляются проанализированными. |
| Просьба прислать счёт | Не разрешает утверждать отправку. Новые черновики, задачи и отправки от такого ответа не появляются. SMTP по-прежнему заблокирован. |
| В архиве «пришлите счёт»/«счёт отправлен» | Импорт не создаёт активных обращений, черновиков, уведомлений или подтверждённых решений. Почтовые контейнеры переписки отделены от сервисных обращений. |
| Противоречащие источники | Явные сравнимые значения одного параметра выявляются; молчаливый выбор заглушки отклонён. Семантические противоречия и реальное качество их объяснения требуют проверки модели и инженера. |
| Чужие закрытые данные | Проверены права сотрудников/клиентов, владельцы диалогов и файлов, отзыв разрешения, закрытые оригиналы и отсутствие сырой почты в клиентских источниках. |
| Повторный импорт | Проверены хеши, ID сообщений, редакции, пересекающиеся партии, восстановление после ошибки и отдельные пропуски файлов. |
| API недоступен | Проверен настоящий браузерный путь с отсутствующим ключом и SDK-заглушка с исключением: явная ошибка, без цитат вместо ответа, сохранение диалога и вложений. |

Текстовые эвристики и успешные тесты не гарантируют все возможные формулировки. Версия записи и SHA-256 позволяют отличать файлы; официальная редакция руководства не угадывается по номеру записи. Сведения о цене, наличии, сроках и совместимости из старого письма не становятся текущими фактами. Сырые архивы, гипотезы и ответы самого ИИ исключены из подтверждённых решений.

## Как повторить без программирования

1. Обновите прежнюю папку по [инструкции Windows](../TESTING_GUIDE_RU.md), оставив свой `.env`, БД и `storage`; перед заменой остановите сервер и сделайте резервную копию.
2. В «Настройках» нажмите проверку моделей. Успех требует завершённого структурированного ответа основной модели в формате рабочего чата, а не одного наличия её имени в списке. Остальные модели, которые не вызывались, обозначены как непроверенные. Сам ключ в чат не отправляйте.
3. В базе знаний выберите одно техническое руководство и разрешите ответы по нему. Сам оригинал можно оставить внутренним. Подтвердите точную модель, проверьте состояние обработки и предупреждения OCR.
4. В новом чате пройдите пять реплик из таблицы. Затем назовите модель и уже выполненную проверку, задайте вопрос другими словами и попросите объяснить ответ проще. Сравните источник со страницей руководства. Не проверяйте стороннюю модификацию по похожему руководству.
5. Прикрепите короткое видео. Проверьте, отмечено ли оно как полученное, обработанное по кадрам или с ошибкой. Последующее сообщение должно учитывать уже полученный файл.

Для автоматического сравнения на Windows из папки приложения:

```powershell
.\.venv\Scripts\python.exe -m scripts.dialogue_diagnostics --live --material "C:\путь\к\одному\руководству.pdf"
```

Команда использует ключ из локального окружения/`.env`, работает с временной копией приложения и ограничивает число генераций. Прямой диагностический запрос временно обходится без корпоративного поиска; производственные правила от этого не меняются. Отчёт сохраняется локально в `artifacts`, может содержать конфиденциальные ответы и не входит в программный ZIP. Без `--live` внешних вызовов нет, успешная интеграция не заявляется. `--capture-content` используйте только для отдельного приватного аудита.

## MAX

Проверен универсальный ZIP-импорт с сохранением исходников, автора/времени/ID/ответов при их наличии, связей вложений и отчёта о пропусках. Различаются получение сообщений, наличие файлов, обработка содержимого и доступность поиску. Он не выдаётся за официальный формат MAX.

Наличие полного официального экспорта обычной группы без бота не подтверждено. Нужны платформа/версия клиента и пилот из 10–20 настоящих сообщений с оригиналами фото, видео и документа. Пароли, коды входа и session-токены не нужны. Подробно: [исследование MAX](MAX_INVESTIGATION_2026_11_09_RU.md).
