# План POSTEKS AI

Текущее изменение — первая локальная основа по доступным материалам. Полный продукт из ТЗ имеет более широкий объём. Фактические проверки и ограничения см. RELEASE_VALIDATION.md.

| Этап | Состав | Критерий |
| --- | --- | --- |
| 1. Аудит | Проверка репозитория и входных файлов | Доступные материалы разобраны; аудит старого кода ждёт исходников |
| 2. Веб | Публичный чат, закрытый кабинет, адаптивная оболочка | Реальные CRUD/API, нет выдуманных обращений |
| 3. Знания | Загрузка, страницы, поиск, просмотр источника, Playground | Реальные руководства индексируются; внутренние документы недоступны гостю |
| 4. Почта | Безопасный ручной EML-импорт, threading, черновики, согласование | Дедупликация и блокировка отправок проверены; подключение Яндекса требует реквизитов |
| 5. Обращения | Карточки, заметки, поручения, импорт реестра | Номер СО назначается человеком; данные сохраняются |
| 6. Решения | Кандидат → подтверждение → поиск | Неподтверждённые решения не попадают в ответы |
| 7. PWA | Манифест, адаптивность, статический shell | Установка требует HTTPS/localhost; App Store/Google Play не опубликованы |
| 8. Эксплуатация | Инструкции Windows, резервирование, перенос | Cloud/Linux проверяются; Windows и VPS проверяются на целевой машине |

## После получения исходного проекта

Аудит и объединение с прежним кодом/историей; миграции исходной БД; длительная возобновляемая синхронизация Яндекс Почты; очередь и отдельные воркеры; полноценные роли подразделений; вложения переписки; мультимодальный анализ фото/видео/аудио; семантический индекс embeddings и гибридный поиск; проверка выбранных моделей на реальном ключе; регрессионные наборы AI с контрольными действиями; эксплуатационный аудит и проверка персональных данных для выбранной площадки.

Ни сохранённая конфигурация среды, ни успешная сборка не означают готовность промышленной системы.
