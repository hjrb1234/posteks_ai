# Обновление POSTEKS: почта, знания и OCR — 26 октября 2026

Это локальная проверочная версия. Программный ZIP содержит код и собранный интерфейс; ваши письма, рабочая БД, `.env`, PDF и реестр в общий архив не входят. Уже сохранённые данные нужно оставить в прежнем хранилище. Подробная инструкция: [TESTING_GUIDE_RU.md](../TESTING_GUIDE_RU.md).

## Что изменено

- «Входящие» разделены на клиентов, сотрудников и отправленные. Письма клиентов сгруппированы по компании/адресу и цепочке; есть просмотр отдельных писем, даты, сортировка, локальные отметки новых. Домены компании и адреса отделов читаются из локального `.env`.
- Письмо — прежде всего переписка. Нужное сервисное обращение сотрудник создаёт отдельным действием. Существующие записи не удаляются; нетронутые автоматические почтовые контейнеры переклассифицируются, а оформленные обращения сохраняются.
- Исправлено продолжение импорта истории после первой порции. «Загрузить последний год» читает доступный период порциями, с контрольными точками и показателями сохранённых писем/оставшихся UID. Обычный первый опрос по умолчанию охватывает только семь дней.
- Почтовый ИИ-черновик использует отдельную задачу: выбранное письмо, цепочку, адресата и вашу цель ответа. Общая фраза сервисного чата о встрече больше не подставляется вместо письма. Без доступной модели показывается ошибка; ручной ответ остаётся доступен.
- По цепочке можно предложить кандидата решения с цитатами. Предложение само не сохраняется и не становится проверенным знанием. Сотрудник проверяет точную модель, результат, ограничения и разрешённый доступ.
- Сбой OCR отдельной страницы не обнуляет весь читаемый PDF. Сохраняются текстовые страницы, оригинал и предупреждение о пропусках. Добавлена диагностика Tesseract, языков и путей Windows; старые ошибочные документы необходимо обработать заново.
- Добавлен необязательный семантический индекс для близких формулировок. Его строит администратор, используются доступные embeddings OpenAI. Сырые письма/непроверенные истории исключены; при отсутствии индекса работает текстовый поиск.
- В базе знаний есть панель состояния поиска по смыслу и ручная обработка порций индекса. Реестр подключён как закрытый источник в AI Playground: точное сопоставление серийного номера или заказчика, без вывода о гарантии и совместимости деталей.
- Почтовые вложения находятся и после переноса папки программы. Если файл кеша отсутствует, система может восстановить его из сохранённого MIME-письма, сверяя размер, SHA-256 и допустимый тип. Повреждённые файлы не перезаписываются молча.

## Как обновить уже установленную программу

1. Остановите сервер через Ctrl+C в его окне. Закрытие страницы браузера сервер не останавливает.
2. Из прежней папки проекта выполните резервирование, а `.env` отдельно сохраните в защищённую локальную папку:

   ```powershell
   .\.venv\Scripts\python.exe -m scripts.manage backup --directory 'D:\POSTEKS-private-backups'
   ```

3. Распакуйте новый ZIP отдельно. Скопируйте программные файлы из `posteks_ai` в прежнюю папку программы; оставьте существующие `.env`, `storage`, БД, `.venv`, `backups` и все личные материалы. Не очищайте папку перед копированием. Если данные лежат вне папки программы, оставьте прежние абсолютные пути в `.env`.
4. Сравните новый `.env.example` со своим `.env`: добавьте `CORPORATE_EMAIL_DOMAINS` с действительным доменом, сохраните адреса отделов и учётные данные. Секреты нигде повторно публиковать не нужно.
5. Запустите `install.bat`, дождитесь завершения. Затем `start.bat` и `open-app.bat`. Установщик применяет миграции; запускать старый код с новой схемой после этого нельзя. Для отката нужен прежний код вместе с согласованной резервной копией БД и storage.
6. В диагностике сравните фактические пути и прежние документы/переписку. Если видите пустую новую базу, сначала проверьте путь — не импортируйте поверх неё неизвестный старый `posteks.db`.

## Что проверить в первую очередь

1. **Почта:** клиентские письма видны отдельно от `posteks.ru` и собственного сервисного ящика. Откройте компанию, затем цепочку: проверьте обе стороны переписки и вложение. Измените сортировку/диапазон. Новая независимая тема без почтовых ссылок должна остаться отдельной цепочкой.
2. **История:** нажмите «Загрузить последний год». Оставьте сервер запущенным, дождитесь окончания всех порций и проверьте ошибки/контрольные точки. Двадцать два письма во вкладке не доказывают полноту года — это может быть отфильтрованный недавний список.
3. **Черновик:** на уведомлении об адресе или запросе документа проверьте текст именно по задаче письма и внешнего адресата. «На согласовании» означает сохранённый черновик для сотрудника; фактическая отправка и бронирование визита не выполняются.
4. **PDF:** выполните `python -m scripts.install_ocr --check` через `.venv\Scripts\python.exe`, настройте Tesseract по [инструкции](OCR_WINDOWS_RU.md), перезапустите сервер и выберите «Обработать заново» на прежних ошибочных документах. Предупреждение с пропусками не считайте полным распознаванием.
5. **Знания из переписки:** выберите цепочку с реальным техническим решением, подготовьте кандидата, проверьте цитаты и сохраните. Утвердите и разрешите клиентское использование отдельно. В Playground задайте переформулированный вопрос и проверьте источник; непрочитанные страницы или неподтверждённая переписка не должны превращаться в уверенный совет.
6. **Реестр:** импортированный Excel остаётся в БД оборудования. Для проверки найденной записи используйте точный серийный номер; владение машиной само по себе не доказывает гарантию или совместимость ремня. Закрытые реквизиты клиентов должны оставаться доступны только сотрудникам.
7. **MAX:** импорт готового TXT/JSON/CSV доступен без бота через предпросмотр. Полная официальная выгрузка обычной группы за все годы пока не подтверждена; порядок получения архива и вопрос поддержке — в [MAX_IMPORT_RU.md](MAX_IMPORT_RU.md).

Поиск не требует совпадения вопроса буква в букву. Но наличие письма в списке и готовое проверенное решение — разные состояния. Ответ по смыслу зависит от доступных источников, их применимости к модели, готовности поиска и действующей модели OpenAI. Цель сократить долю ручной работы на 80% потребует проверки на реальных вопросах; текущие изменения сами по себе такой результат не подтверждают.

Код, API и сборка проверяются в облачном Linux. Реальные подключения к вашему Яндексу, полная история MAX и запуск Tesseract/установщика на вашем Windows в этой среде не проверены; завершённые автоматические проверки перечисляются отдельно при передаче сборки.
