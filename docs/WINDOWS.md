# Подробный запуск POSTEKS AI на Windows 10/11

## 1. Скачайте правильный комплект

Используйте переданный локальный **POSTEKS_AI_2_0_Windows.zip**. Версия на GitHub может быть старее этой локальной поставки. В нём уже собран frontend, поэтому для запуска готового пакета нужен Python, а Node.js не обязателен. ZIP не содержит исходных закрытых документов компании, рабочих записей БД, логинов, паролей или API-ключей.

Распакуйте архив целиком, например в `C:\POSTEKS\posteks_ai`. Не запускайте BAT-файлы прямо из окна ZIP. Если Windows показывает кнопку «Извлечь всё», сначала воспользуйтесь ей. Для переноса существующей установки выбирайте новую папку, не перезаписывайте свою .env/storage/резервные копии.

Если скачали GitHub «Code → Download ZIP» или клонировали исходники, дополнительно установите Node.js 22 LTS: https://nodejs.org/ . Такая копия не содержит frontend/dist и соберёт его при установке.

## 2. Материалы и просмотр текущей версии

Если вместе с программой передан отдельный `POSTEKS_materials_PRIVATE.zip`, он содержит возвращаемые вам PDF и реестр, а не программу. Это частные документы вашей компании; не публикуйте архив. Если оригиналы уже находятся у вас, можно использовать их вместо второго архива.

Для первой установки распакуйте **оба ZIP в одну новую родительскую папку**, например `C:\POSTEKS`. Оба архива содержат корневую папку `posteks_ai`: первый добавит программу, второй — `posteks_ai\storage\imports`. При вопросе Проводника разрешите объединение папок. Частный комплект не заменяет `.env` или рабочую БД. Убедитесь, что нет лишнего вложения `posteks_ai\posteks_ai`.

Затем выполните установку: она один раз загрузит материалы из `storage\imports` в закрытую библиотеку и реестр, а повторный запуск определит дубликаты. Если `STORAGE_DIR` или прежний `SERVICE_STORAGE_ROOT` указывает на другой каталог, перенесите `imports` в него либо задайте путь явно: `python -m scripts.manage import-sources --directory 'C:\POSTEKS\posteks_ai\storage\imports'` через Python вашего venv. При обновлении существующей установки следуйте разделу обновления в `TESTING_GUIDE_RU.md`, а не распаковывайте что-либо поверх рабочей базы.

Для просмотра текущих страниц запустите локальный сервер по шагам 3–5 и откройте `open-app.bat`. Так проверяются меню, формы, загрузка PDF, переписка и сохранение данных после перезапуска. `frontend/dist/index.html` не предназначен для открытия двойным щелчком: интерфейсу нужен API сервера.

Автономный TEST HTML предыдущей версии сохранён как прежний материал и исключён из новой поставки. Он не служит проверкой работоспособности этой версии.

## 3. Установите Python

Установите 64-битный Python 3.11 или новее с https://www.python.org/downloads/windows/ . В установщике включите **Add Python to PATH** и Python Launcher. После установки заново откройте терминал.

Проверка в PowerShell:

```powershell
py -3 --version
```

Если `py` отсутствует, проверьте `python --version`. Если открывается Microsoft Store вместо версии Python, установите Python с python.org и проверьте PATH/«Псевдонимы выполнения приложений» Windows. Сам проект системный Python не заменяет: зависимости будут в отдельной `.venv`.

## 4. Установите приложение

В папке проекта запустите **install.bat**. Либо откройте PowerShell в этой папке и выполните:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1
```

Команда разрешает выполнение только указанного локального скрипта в данном процессе PowerShell; глобальная политика не меняется. Скрипт проверит Python и остановку сервера до изменения зависимостей, создаст `.venv`, установит закреплённые зависимости с проверкой SHA-256, сохранит существующую SQLite/storage перед миграциями и использует готовый frontend. При первой установке создаётся новая БД. В исходниках без сборки дополнительно проверит Node.js и выполнит `npm ci`/build. Для намеренной пересборки: `install.ps1 -RebuildFrontend`.

Нужен доступ к серверам установки Python-пакетов; при сборке исходников — к npm. Если установка сообщила об ошибке, прочитайте последнюю строку и не запускайте следующую команду до исправления. Повторный запуск не удаляет `.env` и данные.

## 5. Запустите сервер и создайте администратора

Запустите **start.bat**. При первом старте введите имя администратора и дважды пароль от12 символов. Пароль при вводе не отображается — это ожидаемо. Общего пароля в комплекте нет.

Оставьте окно сервера открытым. Когда появится сообщение о готовности Uvicorn, откройте `open-app.bat` или введите в браузере:

- Клиентский интерфейс: `http://127.0.0.1:8080`
- База знаний сотрудников: `http://127.0.0.1:8080/admin/knowledge`
- Входящие: `http://127.0.0.1:8080/admin/inbox`

Войдите через «Рабочее пространство» с только что созданной учётной записью. Для остановки нажмите Ctrl+C в окне сервера. Закрытие браузера само по себе сервер не останавливает.

## 6. Загрузите документы и реестр

Программный ZIP не содержит рабочих записей БД. Если до установки добавлен частный комплект в `storage\imports`, установщик импортирует его документы и реестр; без частного комплекта начальная библиотека пустая. Войдите сотрудником, откройте «База знаний → Добавить документ». Новые документы закрытые. Дождитесь статуса «В поиске», задайте вопрос в правой панели и откройте источник. Оригиналы сохраняются в `<STORAGE_DIR>\documents`; по умолчанию это `storage\documents`.

Клиентский чат видит только явно опубликованные документы. Для разрешённого публичного руководства меню `··· → Открыть посетителям` потребует подтверждения. Не публикуйте внутренние документы.

Excel-реестр добавляется в разделе «Оборудование». Конфликтующие номера выводятся в отчёте и не объединяются автоматически. Чужую исходную posteks.db не копируйте поверх новой базы: схемы могут отличаться; необходим отдельный перенос.

Для PDF-сканов нужен Tesseract OCR 5. Инструкция проекта: https://tesseract-ocr.github.io/tessdoc/Installation.html . Установите бинарный Tesseract, добавьте его папку в PATH, откройте новый терминал и проверьте `tesseract --version`. Затем повторите install.bat: он загрузит rus/eng из закреплённого официального источника с проверкой SHA-256. После этого нажмите «Обработать заново» у документа с ошибкой OCR. PDF с текстовым слоем могут работать без Tesseract.

## 7. OpenAI и Яндекс — по необходимости

Откройте локальный `.env` в редакторе. В `OPENAI_API_KEY` добавляется ваш ключ; в «Настройки» задаются модели и отдельно проверяется доступность. Не отправляйте ключи в чат, не вставляйте во frontend и не добавляйте .env в Git. После изменения .env перезапустите сервер.

Без ключа работает обозначенный локальный поиск. В настоящем клиентском чате не будет выдуманного AI-ответа. Реальный OpenAI в этой облачной проверке не использовался.

Для голосового ввода запись ограничена 120 секундами. PCM WAV проверяется встроенным обработчиком. Для WebM/OGG/M4A/MP3 и записи микрофона установите FFmpeg с `ffprobe` из доверенного источника, указанного на [официальной странице загрузки](https://ffmpeg.org/download.html), добавьте его `bin` в PATH либо задайте `FFPROBE_PATH=C:/Tools/ffmpeg/bin/ffprobe.exe` в локальном `.env`. Перезапустите сервер. `ffprobe -version` должен показывать установленный обработчик. При отсутствии `ffprobe` сжатые форматы явно недоступны; можно загрузить PCM WAV. Распознанный текст проверяйте перед отправкой. Наличие FFmpeg не подтверждает доступность модели распознавания вашего аккаунта OpenAI.

Для IMAP задайте MAIL_USERNAME и MAIL_APP_PASSWORD. Кнопка «Проверить подключение» проверяет реальную авторизацию и ящик только для чтения. «Синхронизировать сейчас» создаёт задачу импорта; фоновый опрос включается отдельно. Подробные настройки, исторический импорт, контрольные точки и проверка реальным тестовым письмом описаны в [TESTING_GUIDE_RU.md](../TESTING_GUIDE_RU.md). Для воспроизводимой проверки без Яндекса можно импортировать `tests\fixtures\service-request.eml` — вымышленное тестовое письмо. Даже согласованное письмо не отправляется: SMTP заблокирован сервером во всех режимах. Реальная почта с вашими учётными данными в облаке не проверялась.

## 8. Резервирование и забытый пароль

В папке проекта, при остановленном сервере:

```powershell
.\.venv\Scripts\python.exe -m scripts.manage backup
.\.venv\Scripts\python.exe -m scripts.manage create-admin --username admin --reset
```

Первая команда создаёт snapshot SQLite и всего приватного storage (документы, история, почтовые вложения) в backups. .env хранится отдельно; кэши/OCR-данные/символические ссылки исключаются. Вторая явно сбрасывает пароль указанного администратора и завершает его сессии. Не копируйте резервные копии в GitHub. Перед install.bat остановите сервер: обновление сохраняет дополнительную приватную копию до миграций. Пошаговый перенос и откат без смешивания разных схем — в [TESTING_GUIDE_RU.md](../TESTING_GUIDE_RU.md).

## 9. Типовые проблемы

| Сообщение | Действие |
| --- | --- |
| Python/py не найден | Установить Python с PATH, открыть терминал заново |
| npm не найден | Установить Node22 LTS для исходников либо использовать готовый Windows ZIP |
| Скрипт PowerShell запрещён | Запустить install.bat или приведённую команду с -ExecutionPolicy Bypass для этого процесса |
| OCR/rus недоступен | Установить Tesseract, проверить PATH, повторить install.bat, переиндексировать документ |
| Порт8080 уже занят | Проверить предыдущее окно POSTEKS и остановить его Ctrl+C; не завершать неизвестные процессы |
| Внутренний документ не виден в чате | Проверить доступ; внутренние материалы ищутся в Playground, публикация делается отдельно |
| Ошибка соединения с API | Убедиться, что start.bat работает, проверить .env и явную проверку подключения |
| Неизвестная схема БД | Не удалять данные и не присваивать версию вручную; выбрать новую папку и провести аудит старой базы |

Фактические автоматические проверки выполняются в Linux/Chromium. Выполнение BAT/PowerShell на самой Windows в этой среде не подтверждено. Конфигурация и пакеты Windows проверены в пределах доступных инструментов, поэтому результаты целевой установки нужно сообщить отдельно.
