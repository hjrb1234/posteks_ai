# Размещение и эксплуатация

Это план следующего этапа, а не подтверждение готового production-развёртывания.

## Сначала локальная приёмка

Получить недостающие исходники и провести объединение с существующей системой. Отдельно проверить реальные OpenAI и Яндекс с реквизитами владельца. Не включать автоматические отправки: текущая версия их не поддерживает. Завершить проверку доступа документов и персональных данных.

## Целевая схема

- Отдельный согласованный домен, например `support.posteks.ru`. Основной сайт `posteks.ru` не менялся; DNS и публикация требуют решения владельца.
- Reverse proxy Caddy/nginx с HTTPS, ограничением размера запросов и безопасным forwarding только от доверенного proxy. `PUBLIC_BASE_URL` — утверждённый HTTPS-домен, `COOKIE_SECURE=true`, точные `ALLOWED_ORIGINS`, без wildcard.
- Сервер FastAPI на loopback. Для этой SQLite/встроенной очереди используйте один процесс. Перед несколькими воркерами нужны отдельная устойчивая очередь и общий лимитер/бюджет AI.
- PostgreSQL после отдельного пробного переноса: SQLAlchemy URL с драйвером psycopg, миграции Alembic, учётная запись с минимальными правами. Схема может создаваться на PostgreSQL, но перенос истории в этой версии не реализован.
- Приватный постоянный том для `storage/documents`, `storage/registry_imports` и БД; секреты в защищённом серверном окружении, не в архиве исходников. Доступ только сервисной учётной записи и уполномоченным администраторам.
- Отдельные фоновые воркеры и возобновляемые задания нужно добавить до длительных исторических импортов. В текущей версии индексация — один поток внутри процесса с восстановлением queued/processing при старте; распределённой очереди нет.

## Обновление и откат

1. Остановить приложение и дождаться индексации/сохранения текущих операций.
2. Сделать резервную копию новой SQLite через `scripts.manage backup`; исходную старую БД хранить отдельно и не модифицировать.
3. Для PostgreSQL использовать `pg_dump` с параметрами сервера через защищённый service/env, без пароля в командной строке; проверить восстановление в отдельную БД.
4. Сохранить предыдущую версию кода, lockfiles и резервную копию данных.
5. Установить зависимости по lockfile, собрать frontend, применить миграции, запустить проверки.
6. Выполнить smoke при отключённых отправках, затем контролируемо переключить трафик.
7. При откате остановить сервис и восстановить предыдущую согласованную пару «код + БД + документы». `alembic downgrade base` удаляет новую схему и применяется только к одноразовой тестовой базе, не к рабочей истории.

## Мониторинг и ограничения

Проверять `/api/health` из доверенной сети, журнал ошибок, место на диске, статусы документов и регулярность резервных копий. Health означает доступность HTTP/БД, а не успешность OpenAI/IMAP. Текущее наличие ключа — только configured; подключение проверяется отдельно. В production добавьте централизованное наблюдение и оповещения без тел писем, API-ключей и паролей в логах.

Веб-страницы `/service` и `/support` отдаются как обычный HTML. Sitemap остаётся пустым без утверждённого HTTPS `PUBLIC_BASE_URL`; позиции и частотности не исследовались и не обещаются. Админка/API/чаты имеют noindex, API — no-store. Robots и noindex не заменяют проверку прав.

Политику хранения переписки, резервных копий, логов и персональных данных должен утвердить владелец под выбранную территорию размещения. До этого не переносите коммерческую историю в общедоступную систему. Добавьте процедуру удаления и восстановления, мониторинг сбоев и проверку прав сотрудников.

PWA устанавливается в поддерживаемом браузере при HTTPS или localhost, требует сервер для операций с данными. Это не нативная сборка и не публикация в App Store/Google Play. Следующий мобильный этап: Capacitor после проверки авторизации, разрешений микрофона/камеры, офлайн-состояний и правил магазинов.
