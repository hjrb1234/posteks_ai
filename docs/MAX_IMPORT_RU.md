# Приватная история переписки и MAX

Повторная проверка официальной схемы 12 ноября: Bot API `0.0.34`; ограничения получения истории обычной группы остаются неподтверждёнными. Результат повторной проверки добавлен в [исследование MAX](MAX_INVESTIGATION_2026_11_09_RU.md).

POSTEKS принимает историю с предварительным просмотром и отдельным подтверждением сотрудника. Оригинал хранится приватно; архивные просьбы и ответы не становятся текущими командами, отправками или подтверждёнными решениями. В проверенную базу можно добавить только отдельно рассмотренное и очищенное решение.

Исследование для обычного группового чата без бота, проверенные источники и ограничения: [MAX_INVESTIGATION_2026_11_09_RU.md](MAX_INVESTIGATION_2026_11_09_RU.md). Текстовые TXT/JSON/CSV и переносной ZIP POSTEKS — входные форматы нашего импортёра, а не заявление о наличии такого экспорта в MAX.

## Ваш обычный многолетний чат, в котором нет бота

Для загрузки **готового файла переписки** бот MAX не нужен. POSTEKS принимает TXT/JSON/CSV через «База знаний → Импорт истории», сохраняет оригинал закрытым; выделенные из переписки решения должен проверить сотрудник. Для этого сначала нужен сам текстовый архив; название или ссылка на обычный чат не дают POSTEKS доступ к его истории.

**Полный экспорт обычного группового чата из официального клиента пока не подтверждён.** При повторной проверке 9 ноября 2026 года сайты [help.max.ru](https://help.max.ru/), `dev.max.ru` и `legal.max.ru` отклонил сетевой прокси среды (HTTP 403); прямое подключение не разрешило DNS. Это ограничение данной проверки, а не доказательство отсутствия функции в MAX. Доступна официальная схема Bot API на GitHub, но она описывает ботов, а не выдачу истории обычного участника. Поэтому здесь не указана выдуманная кнопка «Экспорт». Возможность получить полное содержимое группы через запрос персональных данных также не подтверждена: архив данных аккаунта может отличаться от архива всех сообщений группы.

Практический порядок для вашего чата:

1. Сохраните существующий чат и проверьте актуальную официальную настольную версию MAX. Если в ней действительно есть экспорт/выдача данных, сначала выгрузите небольшой период и проверьте, что файл содержит **тексты сообщений, автора и время**, а не только список чатов или идентификаторы. Не требуется копировать многолетнюю переписку вручную или снимать её скриншотами.
2. Если соответствующей функции нет в вашей версии либо её формат непонятен, уточните у официальной поддержки MAX через [справку](https://help.max.ru/), доступен ли экспорт для участника или администратора обычной группы. Готовый текст запроса:

   > Нужен машиночитаемый архив обычного группового чата за весь доступный период для внутренней базы технических решений компании. В группе сейчас нет бота. Как официально получить тексты сообщений с авторами и датами, желательно связями ответов и вложениями? Доступно ли это участнику или нужен администратор? Содержит ли выдача данных аккаунта всю групповую переписку, включая сообщения других участников, и какие у неё ограничения по периоду и формату?

3. Когда появится файл, проверьте его состав локально. Подходящий TXT/JSON/CSV можно импортировать сразу; HTML/ZIP или иной официальный формат сначала требует отдельного преобразования. Не переименовывайте произвольный архив в JSON. Для дальнейшей проверки достаточно сообщить формат, версию клиента, свою роль в группе и структуру полей без содержания частной переписки.
4. После получения архива загружайте части через предпросмотр POSTEKS. Рекомендации остаются непроверенными до решения сотрудника; клиентам нельзя отдавать весь сырой чат. Повторный импорт того же файла определяется по хешу.

Добавление нового бота — **отдельный, необязательный вариант**, требующий разрешения администратора компании. Оно не доказывает доступ ко всей истории, накопленной до добавления бота, и не заменяет подтверждённый экспорт обычного чата. Скрипт ниже проверяет лишь сообщения, которые официальный API реально разрешит прочитать. Он не входит в личный аккаунт и не использует session-токены клиента.

## Что подтверждено об API MAX

Повторно получена **9 ноября 2026 года** [официальная схема Max Bot API](https://github.com/max-messenger/api-schema/blob/main/schema.yaml), версия `0.0.33`. Она прямо описывает взаимодействие **ботов** с MAX. Для `GET /messages` указаны предел 1–100 сообщений (по умолчанию 50), порядок от новых к старым и границы `after/before`; прежние `from/to` помечены устаревшими. Ошибка 403 означает отсутствие доступа бота к чату. Для групповых обновлений в схеме отдельно указано право администратора `read_all_messages`. Это не полномочия обычного пользователя и не обещание всей истории до добавления бота.

Схема указывает сервер `platform-api2.max.ru` и передачу токена бота заголовком `Authorization`, а не параметром URL. Страницы [обзора API](https://dev.max.ru/docs-api), [метода сообщений](https://dev.max.ru/docs-api/methods/GET/messages) и [прав в чатах](https://dev.max.ru/docs-api/use-cases/bot-in-chats-and-channels) при текущей проверке заблокированы прокси; доступность конкретного старого периода в настоящем чате не проверялась.

Для разрешённой бот-интеграции предусмотрен путь: официальный бот с разрешением администратора → пробная выгрузка нужного старого периода → проверка результата → текстовый импорт в POSTEKS. Это не инструкция полного экспорта обычного чата без бота. Документация **не гарантирует всю историю до добавления бота или полную выгрузку за все годы**. Доступность старейшего нужного периода необходимо проверить в вашем чате. Живого доступа к вашей переписке здесь не было.

[Официальная справка](https://help.max.ru/) при текущем запросе недоступна из этой среды; меню полного экспорта личного аккаунта и его формат не подтверждены. Нельзя утверждать ни наличие кнопки «Экспорт», ни отсутствие такой функции. Если ваша официальная версия клиента предлагает выдачу данных, можно использовать этот файл после проверки формата. Пароли, коды входа и session-токены для проверки в чате не нужны.

API бота и личная история пользователя — разные полномочия. Сырой JSON MAX содержит текст во вложенном `body`, автора в `sender`, чат в `recipient`, время в `timestamp`. Он **не совпадает** с универсальным форматом импорта POSTEKS ниже и требует преобразования с сохранением происхождения сообщений. Скриншот не заменяет текстовый экспорт участников, времени, связей и полного текста.

## Локальная выгрузка официальным ботом

В проект включён необязательный `scripts/export_max.py`. Он выполняет только чтение `GET /messages`, не отправляет сообщения и не получает доступ к личному аккаунту. Для него нужен **отдельный токен MAX-бота**, которому администратор компании разрешил доступ к нужному чату. Telegram `BOT_TOKEN` не используется.

1. В локальном `.env` заполните `MAX_BOT_TOKEN=` либо задайте эту переменную в защищённом окружении. Токен не передаётся параметром командной строки или URL. При запуске из интерактивного терминала его также можно ввести в скрытом приглашении.
2. Получите точный ID чата из разрешённой интеграции/официального события MAX (`recipient.chat_id`). Название чата не является ID; скрипт не перебирает чужие чаты и не угадывает идентификаторы.
3. Сначала проверьте небольшой нужный старый период. Пример запуска из папки приложения на Windows:

```powershell
.\.venv\Scripts\python.exe -m scripts.export_max --chat-id=-123456789 --from-date "2025-01-01T00:00:00+05:00" --to-date "2025-01-07T23:59:59.999+05:00"
```

Замените ID и даты своими. Явный `+05:00` соответствует Екатеринбургу. Дата вида `2025-01-01` без времени означает целый день **UTC**, что отличается от местного календарного дня.

4. По умолчанию результат находится в `<STORAGE_DIR>/history_exports/max-history-…`; поддерживается прежний `SERVICE_STORAGE_ROOT`. Все относительные пути считаются от папки проекта. Явный `--output` выбирает другой приватный каталог. Каждый запуск создаёт новую папку и не заменяет предыдущую выгрузку.
5. Прочитайте `manifest.json`: запрошенный период, фактически полученные старейшее/новейшее сообщения, количество, ошибки, предупреждения и SHA-256 частей. `completeness` всегда остаётся `unknown`: даже исчерпание видимого API-окна не доказывает доступ ко всем годам или сообщениям до добавления бота. Сверьте нужный старый период с официальным клиентом.
6. В POSTEKS импортируйте **только `messages-*.json`** через предпросмотр и подтверждение. `manifest.json` — отчёт, а не импортный файл. Части автоматически ограничены 5 МиБ и 10 000 сообщений; в них сохраняются текст, автор, время, ссылки на ответы/пересылки и исходная запись MAX. Вложения автоматически не скачиваются.

За один запуск по умолчанию разрешены 200 запросов и 20 000 сообщений, суммарно до 64 МиБ. Лимиты можно явно изменить через `--max-requests` (до 2000) и `--max-messages` (до 100 000), но для больших архивов удобнее последовательно выгружать меньшие периоды. Повторы HTTP 429 ограничены; ответы авторизации и токены не печатаются. Если на одной миллисекунде находится 100 или больше сообщений, скрипт останавливается с предупреждением о неоднозначной границе, а не молча пропускает остаток.

Код выхода `0` означает исчерпание видимого окна, `2` — частичный результат: уже полученные записи сохранены, причина указана в manifest. Код `1` — ошибка конфигурации или сохранения. Выгрузки и токены храните приватно; они не входят в программный ZIP и не предназначены для GitHub. Автоматические тесты используют фиктивный API; доступ к вашему настоящему чату здесь не проверялся.

## Форматы

Максимум 5 МиБ на файл, до 10 000 текстовых записей JSON/CSV, UTF-8 или Windows-1251. Оригинал сохраняется целиком. Для TXT авторы и время не угадываются: это один неструктурированный транскрипт.

JSON — массив объектов либо объект с `messages`:

```json
{
  "messages": [
    {
      "conversation_id": "service-thread-001",
      "date": "2026-10-20T10:00:00+05:00",
      "sender": "Сотрудник",
      "text": "Фиктивный пример: передали вопрос инженеру на проверку."
    }
  ]
}
```

Поддерживаются псевдонимы `chat_id`, `timestamp`, `author/from`, `content/message`; rich-text массивы сохраняют только буквальный текст. Это универсальный контракт POSTEKS, **не заявление о формате официального MAX export**.

CSV — заголовки `conversation_id,date,sender,text`; разделитель запятая, точка с запятой или TAB. Допускаются `чат/диалог`, `дата`, `автор/отправитель`, `сообщение/текст`.

## Проверка импорта

1. Войдите сотрудником и откройте импорт истории в базе знаний.
2. Загрузите файл, проверьте число сообщений, примеры и предупреждения. Просмотр ничего не сохраняет в БД.
3. Подтвердите импорт: архив и внутренний документ сохраняются, запускается индексация.
4. Проверьте оригинал и результат внутреннего поиска. Повторный файл определяется по SHA-256 и не создаёт новый импорт.
5. В отдельном приватном окне клиента убедитесь, что оригинал, transcript и источник недоступны.
6. Не считайте фразу «спасибо» доказательством ремонта. Проверяющий сотрудник должен установить конкретное действие, применимость к модели и источник результата.

API только для сотрудников: `POST /api/history/preview` multipart `file`; `POST /api/history/import` с тем же файлом, `confirmed=true`, `source=MAX` или `manual`; `GET /api/history/imports`; приватный оригинал `GET /api/history/imports/{sha256}/file`. Автоматического обращения к MAX и загрузки чужих переписок эти endpoints не выполняют.
