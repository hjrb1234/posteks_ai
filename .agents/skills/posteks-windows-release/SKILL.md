# Безопасный Windows-выпуск POSTEKS

Применяй при сборке Windows-пакета или выпуске обновления. Не используй для обычного исправления кода, если выпуск не запрошен.

## Порядок

1. Проверь текущие `docs/WINDOWS.md`, `docs/RELEASE_VALIDATION.md`, `scripts/export_project.py`, `scripts/publication_guard.py`, `install.ps1`, `start.ps1`, `tests/test_publication.py`. Если файлы изменились или исчезли, опиши актуальный маршрут.
2. Запусти доступные backend-тесты `.venv/bin/python -m pytest -q`; для затронутого фронтенда из `frontend/` — `npm ci` и `npm run build`. При наличии Chromium — `python -m scripts.browser_smoke` и `python -m scripts.preview_smoke`.
3. Собирай только из проверенного исходного кода и явного allowlist. В известной ветке: `.venv/bin/python -m scripts.export_project` формирует `downloads/posteks_ai_windows.zip` и SHA-256. Не заменяй имеющийся рабочий архив, если не согласовано, как сохранить предыдущее обновление.
4. Проверь ZIP: открытие, контроль CRC, отсутствие приватных путей/файлов/ключей; выполненный вывод публикационного guard и точное значение checksum. `python -m scripts.publication_guard` смотрит **staged**-файлы: нулевое число проверенных файлов не означает, что весь репозиторий или ZIP проверен. Отдельно проверь ZIP по `inspect_zip` или эквивалентным кодом.
5. Подготовь сценарий обновления существующего Windows-пользователя: новая папка/резервная копия, перенос только согласованных данных по документированной процедуре, сохранение `.env`, базы, `storage/`, вложений и резервных копий. Не допускай, чтобы архивация или распаковка перезаписывали рабочие файлы.
6. Если Windows реально недоступна, **не** заявляй, что BAT/PowerShell, установка, миграция и обновление проверены на Windows. Подготовь ручной checklist для Windows 10/11: чистая установка, вход, сохранение данных после обновления, открытие локального адреса, журнал ошибок и откат.
7. Для обновления БД создай отдельный план миграции с backup/restore и проверкой совместимости. Старую `posteks.db` не переписывай и не подменяй новой схемой автоматически.

## Выход

Укажи версию/commit, путь выпуска, SHA-256, размер архива, результаты тестов, отдельную колонку `Проверено в облаке / Нужно проверить на Windows`, контроль исключения секретов и процедуру отката. Не объявляй выпуск production-ready при непроверенных интеграциях OpenAI/IMAP, реальной Windows или данных пользователя.
