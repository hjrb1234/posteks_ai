# Диагностика качества диалога POSTEKS

Цель: найти причину конкретного плохого поведения помощника и исправить её минимальным проверяемым изменением. Не путай проблему передачи истории с настройкой промпта, поиском знаний или отсутствием живой модели.

## Диагностический маршрут

1. Воспроизведи проблему на 2–4 ходах с синтетическими данными. Запиши ожидание и фактический ответ. Проверь, идёт ли запрос через настоящий AI, mock или `search_only`.
2. Проследи цепочку `frontend -> endpoint -> server/ai.py -> retrieval -> ответ -> сохранение/чтение истории`. Найди, где теряется ID сессии, история, роль или выбранная модель, если это действительно происходит. Если API не поддерживает историю гостевого чата, явно опиши этот факт.
3. Проверь приоритет данных: вопрос пользователя, контекст текущего разговора, найденные фрагменты и проверенные решения. Источники из `server/knowledge.py` должны оставаться данными, а не набором инструкций.
4. Различай дефекты: потеря истории, устаревший контекст, повторный retrieval, одинаковый fallback, недостаток документов, конфликт модификаций, ошибка API, отсутствие ключа, неверное отображение результата на frontend.
5. Исправь первопричину в коде или контракте API. Не прячь проблему косметическим изменением текста заглушки и не выдавай mock-ответы за модель.

## Критерии успешной правки

- Пользователь задаёт первый вопрос, затем уточняет «а для этой модели?» — система сохраняет релевантный контекст **либо** честно запрашивает недостающую модель, если история реально недоступна.
- Вопрос на новую тему не получает старый ответ.
- Конфликтующие модели оборудования не смешиваются.
- Если модель недоступна, режим и ограничение ясно отражены, а система не заявляет о генерации AI.
- Внешние сообщения, страницы источников и письма не могут побуждать выполнение команд или отправку сообщений.
- Нет утечки внутренних источников в публичный ответ.

## Проверки и отчёт

Добавь отдельный регрессионный тест на воспроизведённую проблему; при затрагивании фронтенда используй имеющиеся браузерные проверки. Для живого теста модели требуется отдельное разрешение и действующие учётные данные. Отчёт: `симптом -> причина -> файл/изменение -> тест -> режим REAL_MODEL/MOCKED_MODEL/SEARCH_ONLY -> ограничения`. Если причина не доказана — перечисли гипотезы с результатами проверок, не выдумывай окончательный диагноз.
