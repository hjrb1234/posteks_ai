# Проверка POSTEKS AI 2.0 на Windows

После обновления дважды щёлкните `check.bat`. Он проверит локальные файлы и состояние истории почты, затем откроет отчёт. Для запроса к OpenAI на тестовых данных используйте `check.bat -Live`. Для разбора отправляйте только `support_report.json`. [Краткая инструкция](docs/QUICK_START_RU.md) · [Как устроены проверки](docs/SELF_CHECK_RU.md)

Система работает локально. Хостинг, домен и DNS для этих проверок не нужны. SMTP-отправка заблокирована сервером: `SAFE_MODE=true`, `MAIL_SEND_ENABLED=false`. Ни согласование, ни режим интерфейса не разрешают отправку.

Проверки Python/API и сборки выполняются в облачном Linux. Запуск BAT/PowerShell, реальные учётные данные Яндекса и качество ответов на вашем OpenAI-ключе нужно проверить на вашем компьютере. Успешный HTTP 200 сам по себе не подтверждает импорт письма или индексацию PDF.

Если приложение у вас уже работает, начните с [обновления существующей папки](#9-обновление-без-потери-данных-и-откат). Текущая диагностика шаблонных ответов, результаты до/после и короткая проверка: [AI_DIAGNOSTICS_RU.md](docs/AI_DIAGNOSTICS_RU.md). Предыдущие изменения сохранены в [описании от 30 октября](docs/CHANGES_2026_10_30_RU.md) и [описании от 26 октября](docs/CHANGES_2026_10_26_RU.md).

**Без доступной языковой модели обычный чат теперь показывает явную ошибку.** Найденный отрывок не подставляется вместо ответа ИИ. Поиск документов остаётся отдельной функцией. Проверочные браузерные сценарии старых рабочих процессов включают явный режим текстового справочника только в TEST; это не проверка настоящей модели и не настройка для рабочей установки.

## 1. Первый запуск

1. Создайте папку `C:\POSTEKS_TEST` и распакуйте в неё Windows ZIP. Должен появиться файл `C:\POSTEKS_TEST\posteks_ai\install.bat`. Не запускайте программу внутри окна ZIP.
2. Установите Python 3.11+ x64. Для готового ZIP с `frontend\dist` Node.js не требуется; для Git checkout/пересборки нужен Node.js 22 LTS.
3. Для первой установки отдельный `POSTEKS_materials_PRIVATE.zip`, если он предоставлен, распакуйте в ту же родительскую папку: появится `posteks_ai\storage\imports`. Частный комплект содержит ваши PDF/реестр и не предназначен для публикации; он не заменяет `.env` или БД. Запустите `install.bat`. Существующий `.env` не заменяется примером. При обновлении скрипт требует остановить сервер на порту 8080 и делает приватную копию перед миграциями.
4. Запустите `start.bat`, задайте администратора при первом запуске. Общего тестового пароля нет.
5. Оставьте окно сервера открытым, откройте `open-app.bat`. Клиент: `http://127.0.0.1:8080`, сотрудники: `/admin/inbox`, знания: `/admin/knowledge`.

Закрытие браузера не останавливает сервер. Остановка — Ctrl+C в его окне.

## 2. Если экран пустой: сначала проверьте источник данных

В PowerShell из папки проекта:

```powershell
.\.venv\Scripts\python.exe -m scripts.manage diagnostics
```

Смотрите `database_path`, `storage_dir`, `documents_dir`, наличие таблиц/число строк и предупреждения о `DATABASE_URL`/`DB_URL`, `STORAGE_DIR`/`SERVICE_STORAGE_ROOT`. Значения ключей и паролей не выводятся. В админке также доступна серверная диагностика (`GET /api/diagnostics`, только сотрудникам).

Ноль документов означает ноль документов именно в активной БД, а не отсутствие PDF где-либо на компьютере. ZIP с кодом специально не содержит рабочих БД, писем или внутренних руководств. Их нельзя автоматически восстановить из интерфейса старой установки.

Относительные пути относятся к папке проекта. Если перенесли программу в другую папку, такой же относительный путь может указывать на новое пустое место. Сверьте эффективные пути до и после переноса. При необходимости задайте абсолютные пути к своей рабочей БД и хранилищу; `.env` редактируйте локально, не отправляйте его содержимое в чат.

Старый `posteks.db` неизвестной схемы нельзя переименовать/подключить как новую БД и просто запустить Alembic. Для него предусмотрены отдельные команды ниже; автоматическое присвоение версии запрещено.

## 3. Реальная проверка Яндекс Почты

В своём `.env` заполните учётные данные. Пароль — пароль приложения Яндекса. Пример имён без значений секретов:

```dotenv
APP_MODE=SAFE
SAFE_MODE=true
MAIL_SEND_ENABLED=false
MAIL_IMAP_HOST=imap.yandex.com
MAIL_IMAP_PORT=993
MAIL_USERNAME=
MAIL_APP_PASSWORD=
MAIL_INBOX_FOLDER=INBOX
MAIL_SENT_FOLDER=
MAIL_POLL_ENABLED=false
MAIL_POLL_SECONDS=60
MAIL_INITIAL_DAYS=7
```

Поддерживаются также прежние `IMAP_HOST/IMAP_PORT`, `IMAP_USER/IMAP_USERNAME`, `IMAP_PASSWORD`, `MAIL_ADDRESS`, `MAIL_MAILBOX`. Не задавайте разные значения для одного назначения. После изменения `.env` перезапустите сервер. В TEST реальные подключения отключены.

1. Войдите администратором и нажмите «Проверить подключение». Ожидается реальная проверка авторизации и выбранного ящика в режиме чтения. Наличие заполненных полей означает «настроено», а не «соединение проверено».
2. Самостоятельно отправьте с другого своего адреса письмо с уникальной темой, например `POSTEKS-local-check-<дата-время>`. Приложение за вас письмо не отправляет.
3. Нажмите «Синхронизировать сейчас». Задача ставится в очередь; дождитесь результата в журнале синхронизации. Первичный обычный опрос ограничен последними `MAIL_INITIAL_DAYS` днями.
4. Убедитесь, что конкретное письмо появилось во входящих. Проверьте адрес/тему, время, вложение и цепочку переписки. Повторите синхронизацию: второй экземпляр появиться не должен. Импорт письма сам по себе больше не создаёт сервисную работу в очереди «Обращения»; для неё сотрудник нажимает «Создать сервисное обращение» в нужной цепочке.
5. Подготовьте AI-черновик, проверьте источники и текст, отредактируйте, согласуйте. Любая попытка реальной отправки должна оставаться заблокированной сервером.
6. Включите фоновый опрос в настройках или через `MAIL_POLL_ENABLED=true`, перезапустите при изменении `.env`, отправьте ещё одно тестовое письмо и дождитесь следующего интервала. Проверьте фактический статус обработчика и новый запуск в журнале.
7. Для старой переписки нажмите **«Загрузить последний год»** и подтвердите период 365 дней. Это отдельное задание, а не повтор обычного опроса. Если нужен другой период, используйте параметры истории (до 3650 дней). Задание автоматически проходит несколько порций; вкладку можно закрыть, пока сервер остаётся запущенным. Остановка задачи не удаляет уже импортированные данные, а повторный запуск продолжает с сохранённого UID без второго экземпляра письма.

### Почему сначала видны только недавние письма

Первый обычный опрос ограничен `MAIL_INITIAL_DAYS` (по умолчанию 7), затем получает новые UID. Поэтому число вроде 22 само по себе не означает, что импортирован последний год. Во вкладке клиентов число относится к отфильтрованному списку: внутренние письма и собственные отправленные сообщения показываются отдельно.

В состоянии почты смотрите два разных показателя: **сохранённые IMAP-письма в локальной базе** и **задание истории**. Период и контрольная точка истории хранятся на сервере. «Найдено для этой задачи» и «Осталось» отражают UID текущего импорта, а не число всех клиентов. Счётчик сообщений в папках — снимок ответа IMAP, он может измениться при поступлении новой почты. Даты диапазона IMAP основаны на INTERNALDATE; дата, написанная отправителем в заголовке письма, может отличаться.

Дождитесь завершения всех порций и обеих выбранных папок, включая отправленные. Если показан частичный результат, посмотрите UID и причины пропусков — большой или повреждённый MIME-файл не считается успешно загруженным. Ошибка сети оставляет последний подтверждённый UID для повторной попытки. Запись об импортированной истории не исчезает после последующих обычных опросов.

### Если история останавливается с imap_fetch_failed

Старая общая надпись не позволяла определить, отказал ли сервер при чтении размера, всего письма или его части. В новой версии откройте **«Показать журнал и контрольные точки → Диагностика загрузки»** у нужной задачи: показываются папка, UID, этап и ограниченный код ответа IMAP. Исходный текст письма, пароль и произвольный текст ответа сервера в диагностику не копируются.

Чтение проверяет UID, заявленный размер и полноту MIME. Если сервер отклоняет чтение письма целиком, предусмотрены ограниченные чтения `BODY.PEEK[]` по частям. Они не отмечают письмо прочитанным. Для повторного запуска после обновления нажмите **«Загрузить последний год»** ещё раз: новая задача повторит сохранённые незагруженные UID в выбранном периоде, а уже импортированные письма пропустит как дубликаты. Удалять письма, базу или контрольные точки не нужно.

Одиночный отказ чтения может быть сохранён как `retryable`, чтобы остальные письма продолжили загружаться. Продвижение курсора при этом не означает, что проблемное письмо успешно прочитано: его UID остаётся в отдельном списке повторных попыток, а история считается неполной. После трёх последовательных ошибок загрузка останавливается, чтобы не продолжать бесполезные запросы. Ошибки авторизации, TLS и нарушения протокола нельзя исправлять отключением защиты.

Если ошибка повторится в обновлённой версии, для дальнейшего разбора достаточно записать код ошибки, папку, UID и этап. `imap_fetch_failed` на скриншоте само по себе не доказывает причину отказа настоящего сервера Яндекса; здесь совместимость проверяется на воспроизводимых ответах IMAP без доступа к вашему ящику.

### История писем и накопление знаний

Сохранение письма создаёт историю переписки, но не делает любую старую фразу техническим правилом. Для опыта выберите подходящую цепочку, подготовьте решение с моделью, симптомами, действиями и ограничениями и передайте сотруднику на проверку. Кнопка «Предложить решение из переписки» при доступном OpenAI подготавливает **несохранённого кандидата** с цитатами писем; проверьте его, затем отдельно сохраните. Только проверенное решение с разрешённым доступом может стать источником клиентского ответа. Ассистент не требует буквального совпадения вопроса: текстовый поиск ищет слова и модель, а OpenAI при действующем ключе формирует ответ по контексту и найденным источникам. Это накопление проверенных знаний, а не автоматическое изменение весов модели.

Дополнительно предусмотрен семантический поиск по embeddings, который помогает находить близкие формулировки. Он требует доступной модели embeddings и отдельного построения индекса администратором; сам факт заполненного ключа не означает готовый индекс. Проверка: `GET /api/knowledge/semantic/status`. Построение: `POST /api/knowledge/semantic/rebuild` с `{"include_internal":false,"max_items":50}` через API с действующей сессией администратора. Повторяйте небольшие партии, проверяя `remaining_up_to_limit`, `complete` и `truncated`; общий предел текущего индекса — 500 источников. `include_internal=true` разрешайте только если компания допускает передачу соответствующих закрытых текстов провайдеру OpenAI. Сырые письма, непроверенная история и кандидаты исключаются. При отсутствующем индексе/ключе используется текстовый поиск. Число найденных фрагментов и смысловая близость не подтверждают совместимость запчасти.

В интерфейсе эта операция доступна в **«База знаний → Поиск по смыслу»**: сначала проверьте состояние, затем администратор может обработать очередные 50 фрагментов. Обычное построение использует материалы, разрешённые для клиентских ответов, включая закрытые оригиналы с отдельным разрешением `client_answers`. Остальные тексты только для сотрудников требуют отдельного флажка с объяснением передачи провайдеру. Панель показывает ограничения и оставшуюся работу.

### Клиенты, ответы сотрудников и отправленные письма

В «Входящих» по умолчанию показываются клиенты, сгруппированные по компании/адресу, затем по цепочке. Во вкладках сотрудников и отправленных показывается другая сторона переписки; внутри открытой цепочки сохраняются обе стороны. Для просмотра отдельных записей используйте «По письмам». Порядок задаётся датой самого письма, при её отсутствии — датой импорта; доступны сортировка и диапазон дат. Ключ цепочки строится по почтовым `Message-ID`, `In-Reply-To`, `References`: отдельное новое письмо без таких ссылок считается новой цепочкой даже при похожей теме.

В локальном `.env` оставьте прежние адреса отделов и добавьте фактический домен компании:

```dotenv
CORPORATE_EMAIL_DOMAINS=posteks.ru
DEPARTMENT_KB_EMAIL=
KB_RESPONSE_SENDERS=
DEPARTMENT_MANAGER_EMAIL=
DEPARTMENT_SALES_EMAIL=
DEPARTMENT_ASU_EMAIL=
DEPARTMENT_PRODUCTION_EMAIL=
```

Заполняйте пустые значения только локально. Несколько доменов в `CORPORATE_EMAIL_DOMAINS` разделяются запятыми; адрес собственного ящика берётся из `MAIL_USERNAME`/`MAIL_ADDRESS`. После правок перезапустите сервер. Правило определяет отображение, а не удостоверяет личность отправителя. Предположенное по подписи название компании не является подтверждённым клиентским справочником. Два независимых клиента на `mail.ru` или `yandex.ru` не объединяются лишь по общему домену.

Индикатор нового относится к локальной обработке; открытие цепочки не меняет флаги прочтения в Яндексе. Ранее импортированная история не помечается потоком новых обращений. Старые автоматически созданные почтовые контейнеры сохраняются, а нетронутые из них выводятся из очереди сервисных обращений. Обращения с номером, назначением или явной работой сотрудника сохраняются как сервисные.

ИИ-черновик теперь готовится специально по выбранному письму и контексту цепочки. Проверьте поле «Кому»: собственный сервисный адрес не должен автоматически подставляться как клиент. Без рабочего OpenAI/при ошибке выводится причина, и можно написать ответ вручную; шаблонная фраза о встрече не считается подготовленным письмом. Старые черновики сохранены и могут требовать повторной проверки. «На согласовании» — очередь проверки текста сотрудником, а не отправка письма и не подтверждение визита.

Технические API: `POST /api/mail/check`; `POST /api/mail/sync` с `{"kind":"new","batch_size":100}`; `POST /api/mail/history` с `{"days":365,"batch_size":100}`; `GET /api/mail/status`, `/api/mail/runs`; `POST /api/mail/runs/{id}/stop`. Для настройки worker — `PATCH /api/mail/worker` с `enabled/poll_seconds`. Используйте интерфейс с действующей сессией, не помещайте пароли в URL/аргументы команд.

Смотрите выбранные папки, UIDVALIDITY, последний UID, контрольную точку истории, количество импортированных/дубликатов/ошибок и время последнего успеха. Ошибка сети/авторизации не должна выглядеть как успешно синхронизированный пустой ящик. Подключение выполняется без удаления писем, перемещения и изменения прочитанности. Восстановление незавершённой задачи после аварии может ожидать истечения lease до трёх минут.

Без доступа к реальной почте можно импортировать вымышленный `tests\fixtures\service-request.eml` и проверить интерфейс, дедупликацию и черновики. Это не проверка Яндекса.

## 4. PDF и база знаний

1. Войдите сотрудником: «База знаний → Добавить документ». Загрузите один настоящий PDF PE38-12. Внутренний доступ установлен по умолчанию.
2. Дождитесь завершения стадии обработки: проверка → извлечение/OCR при необходимости → построение индекса → готово. При ошибке проверьте указанную стадию, а не загружайте бесконечно дубликаты.
3. Убедитесь, что счётчик вырос, появились страницы и фрагменты. Выполните запрос с точной моделью и термином из руководства. Откройте именно найденную страницу и сравните цитату с PDF.
4. Во внутреннем Playground документ доступен сотруднику. Без отдельного разрешения он не используется в клиентском чате. В приватном окне браузера клиент не должен получать внутренний оригинал, полную страницу или её изображение.
5. Для допустимого руководства администратор выбирает **«Разрешить ответы клиентам»** в действиях документа. Это `answer_access=client_answers`: помощник получает право использовать выдержки в ответах и передавать их настроенному AI-провайдеру. При `visibility=internal` оригинал остаётся закрытым; для ответа не нужно публиковать весь PDF. Не разрешайте закрытую переписку, внутренние цены или конфиденциальные разделы документа «О компании». Новая миграция не включает разрешение автоматически.
6. Повторная загрузка того же файла должна определить дубликат. Переиндексация обновляет статус. При отзыве разрешения для закрытого оригинала новые ответы и последующее чтение истории заново проверяют доступ: прежний ответ с недоступным источником скрывается. Публичный оригинал (`visibility=public`) остаётся разрешённым источником; для полного отзыва закройте оригинал и установите `answer_access=staff_only`.
7. Перезапустите сервер: документ и оригинал должны остаться. Если исчезли, сравните пути из раздела 2.

В диагностике различаются количество документов и `client_answer_documents` — число обработанных источников с разрешением для клиентских ответов. Наличие PDF в списке ещё не означает такое разрешение. Непроверенную историю переписки нельзя разрешить этим переключателем даже после переименования: сначала создаётся отдельное проверяемое решение.

При проверке семи PDF-вложений от 30 октября обнаружено шесть уникальных материалов: две версии имени файла руководства 5310 содержат одинаковый файл. Вместе это 354 страницы. Дубликаты не нужно импортировать повторно; сами частные PDF в программный архив не включаются.

Для сканов нужен Tesseract OCR 5 с rus/eng; для PDF с текстовым слоем он не обязателен. Один сбой OCR теперь оставляет доступными остальные читаемые страницы, а документ получает предупреждение с номерами пропусков. Предупреждение означает частичную обработку. Полный скан без извлечённого текста остаётся ошибкой; оригинал и реальное число страниц сохраняются. При неудачной переиндексации уже полезный индекс не удаляется.

Из папки проекта выполните:

```powershell
.\.venv\Scripts\python.exe -m scripts.install_ocr --check
.\.venv\Scripts\python.exe -m scripts.install_ocr
```

Первая команда проверяет бинарный Tesseract и языки даже при установке вне `PATH`; вторая готовит закреплённые языковые данные с проверкой SHA-256. После настройки/перезапуска выберите у ошибочных и частично обработанных PDF «Обработать заново». Старые ошибки не исчезают только от копирования кода. Подробности путей, ошибок и ограничений: [docs/OCR_WINDOWS_RU.md](docs/OCR_WINDOWS_RU.md).

Старые DOC/XLS преобразуются через необязательный LibreOffice: установите его и при необходимости задайте `LIBREOFFICE_PATH`. Используется отдельный профиль, макросы и обновление ссылок отключены, время обработки ограничено; оригинал сохраняется. В облаке сам LibreOffice не установлен, поэтому фактическое преобразование бинарных DOC/XLS нужно проверить отдельно. Сложные общие таблицы PE38-17/PE38-25 и технические выводы по изображениям проверяйте инженером: ссылка на страницу не доказывает применимость каждой колонки к конкретной машине.

## 5. AI и длинный диалог

В настройках сначала проверьте доступность моделей для вашего ключа. Заполненное имя модели не гарантирует её поддержку аккаунтом. Без ключа/при ошибке API режим ограничен; не оценивайте его как успешную проверку генерации OpenAI.

Проведите последовательно один разговор из 15–25 сообщений:

1. Спросите о ремнях для PE38-12, сообщите известные маркировки и что не умеете определять нужный параметр.
2. Напишите «не понимаю, где это посмотреть». Ожидается новое понятное объяснение, а не тот же перечень неизвестных характеристик.
3. Приложите читаемую фотографию. Сравните распознанную маркировку с оригиналом; неразборчивый текст должен запрашиваться повторно без выдумывания.
4. Сообщите, что совет не помог, затем явно попросите специалиста.
5. Сообщите модель, контакт, адрес и желаемое время, если оформляете выезд. Проверьте, что эти сведения сохранились, а AI не переключился обратно к поиску отсутствующей инструкции.
6. Ожидается заявка на согласование сотруднику. Подтверждённый визит/сроки/совместимость ремней не должны обещаться без источника или решения сотрудника.

Для технического ответа сверяйте источник и точную модификацию. Для организационного действия отсутствие PDF не должно мешать оформлению запроса. Дополнительно откройте два независимых приватных окна: история и вложения клиентов не должны смешиваться.

### Точная модель, смена темы и роль компании

Для указанной модели поиск рассматривает весь доступный текст подходящего руководства, затем выбирает относящиеся к вопросу страницы, включая разделы деталей. Это не означает, что LLM прочитала каждую страницу и поняла все схемы. Нераспознанные страницы, отсутствующая инструкция и неоднозначные таблицы должны ограничивать вывод. Если запись о детали не найдена, это само по себе не доказывает, что деталь нигде не применяется; готовый ответ про конкретные ремни в код не внесён.

`38-35` и `38-25` считаются разными обозначениями. Если руководства для точной модификации нет, помощник должен сообщить об этом или попросить уточнить шильдик, а не незаметно выбрать похожую машину.

После разговора о детали спросите об актуальности счёта. Следующий ответ должен касаться нового вопроса, не продолжая собирать характеристики прежней детали. Без актуального подключённого учётного источника система не может подтвердить срок действия счёта, оплату, цену или наличие. Сам вопрос о счёте не должен автоматически создавать выезд или передавать обращение сотруднику без соответствующей просьбы.

Если клиент уже сообщил «не знаю» или «не понимаю», проверьте, что ему предлагается другой доступный шаг, без бесконечного повторения того же неизвестного параметра. Посторонняя просьба выполнить школьное задание, в том числе на распознанной фотографии, должна получать объяснение роли сервисного помощника ПОСТЭКС. Обращение по упаковочному оборудованию и сервисным документам при этом остаётся допустимым.

Для дополнительной локальной проверки переформулированных вопросов:

```powershell
.\.venv\Scripts\python.exe -m scripts.manual_evaluation
```

Команда читает активную SQLite только для чтения, не подключается к почте и не вызывает OpenAI. Приватный отчёт сохраняется в `artifacts/manual-evaluation/questions-offline.json`; в нём могут быть выдержки руководств, поэтому он не предназначен для GitHub. Это проверка поиска и маршрутизации, а не оценка качества живой модели. Подробности: [docs/ASSISTANT_EVALUATION_RU.md](docs/ASSISTANT_EVALUATION_RU.md). Ключ OpenAI и реквизиты IMAP в облачной проверке отсутствовали; реальные ответы модели и подключение Яндекса проверяются на вашей установке.

Для проверки голоса запишите до 120 секунд и сначала просмотрите распознанный текст. PCM WAV обрабатывается без дополнительного анализатора; для WebM/OGG/M4A/MP3 нужен `ffprobe` из FFmpeg в PATH или `FFPROBE_PATH`. Ссылка на официальный источник и шаги — в `docs/WINDOWS.md`. Без обработчика или действующего API система должна показывать причину, а не готовую вымышленную расшифровку.

### Реестр как источник для сотрудника

Импортированный Excel используется не только таблицей: в **AI Playground** можно спросить о точном серийном номере (`Серийный номер: …`) или точном названии заказчика. Откройте источник «Реестр» в ответе и проверьте модель, проект и отгрузку. Совпадение ищется по целому номеру с нормализацией пробелов/дефисов, без угадывания по обрывку или телефону. Реестр не подтверждает совместимость детали и действующую гарантию. Закрытые сведения реестра не выдаются публичным клиентским чатом.

## 6. Передача специалисту

В клиентском диалоге явно попросите специалиста. В админке откройте очередь эскалаций: должны быть причина, история/резюме, известные факты, отдел, статус и связанное обращение. Повторное сообщение в том же случае не должно создавать новую независимую заявку.

Назначьте ответственного, возьмите заявку в работу, отправьте локальный ответ в тот же диалог, проверьте его в клиентском окне. Изменение статуса должно сохраняться после перезапуска. Нажатие «Сохранить решение» создаёт кандидата; проверенное знание появляется только после отдельного подтверждения.

Для опыта из почты откройте всю цепочку, включая отправленные ответы. Сохраните применимое решение как кандидата: укажите точную модель, симптомы, действия и ограничения. Повторное сохранение того же кандидата не должно создавать дубликаты. Фраза «спасибо» и импорт переписки не подтверждают техническое решение автоматически: его проверяет сотрудник.

## 7. История чатов, MAX и старый SQLite

В базе знаний доступен импорт TXT/JSON/CSV с предварительным просмотром и явным подтверждением. Он сохраняет оригинал приватно и создаёт внутренний **непроверенный** источник. Импорт не меняет веса модели, не подтверждает автоматически советы и не открывает переписку клиентам. Подробности формата и ограничения MAX: [docs/MAX_IMPORT_RU.md](docs/MAX_IMPORT_RU.md).

Для готового файла из обычной группы MAX бот не нужен. Но получение полного многолетнего архива из официального клиента пока не подтверждено: добавление нового бота не гарантирует доступ ко всей прежней переписке. В инструкции есть точный вопрос официальной поддержке о выгрузке обычной группы; делать тысячи скриншотов не требуется.

Для неизвестной старой SQLite сначала остановите старое приложение:

```powershell
.\.venv\Scripts\python.exe -m scripts.manage inspect-legacy --source 'D:\old-posteks\posteks.db'
.\.venv\Scripts\python.exe -m scripts.manage snapshot-legacy --source 'D:\old-posteks\posteks.db' --directory 'D:\POSTEKS-private-backups' --confirm-stopped
```

Команды читают оригинал, не запускают на нём миграции, не выводят содержимое сообщений. При WAL требуется снимок: копируются БД и WAL в приватную временную папку, восстановление WAL происходит на копии. Не используйте снимок с `INCOMPLETE.txt`.

Для распознанной таблицы документов можно проверить отдельный перенос из полученного `legacy_snapshot.sqlite3`:

```powershell
.\.venv\Scripts\python.exe -m scripts.manage import-legacy-documents --source 'D:\POSTEKS-private-backups\legacy-...\legacy_snapshot.sqlite3' --documents-root 'D:\old-posteks\documents'
```

Сначала получите dry-run. Поддерживаются `documents/knowledge_documents/uploaded_documents` с `filename` и `storage_name/file_path/storage_path/path`. Путь к файлу должен лежать внутри указанного каталога. После проверки повторите команду с `--confirm`: существующая целевая БД и storage резервируются, документы копируются внутрь новой системы с закрытым доступом, оригиналы не удаляются. Это **не перенос пользователей, паролей, писем, обращений и произвольной неизвестной схемы**. Для них нужен аудит доступной копии и отдельное отображение полей.

Предоставленные большие `posteks.db` и архив миграций не были доступны для чтения из-за лимита передачи 32 МиБ. Их содержимое и совместимость не объявляются проверенными. Не запускайте старый `alembic.zip` поверх новой БД только по совпадению названия.

Чтобы передать недостающие материалы на отдельный аудит, подготовьте source-only ZIP без `.venv`, `node_modules`, `storage`, PDF, рабочих БД и `.env`; каждый загружаемый файл должен быть не больше 32 МиБ. Старую SQLite после остановки сервиса и создания согласованного снимка можно отдельно сжать в ZIP — SQLite часто хорошо сжимается. Если он всё равно больше лимита, передавайте сначала отчёт схемы без содержимого сообщений и согласуйте безопасный способ передачи приватной копии. Это приватные материалы для аудита, не содержимое общего Windows ZIP и не основание для публикации в GitHub.

## 9. Обновление без потери данных и откат

1. Остановите сервер POSTEKS через Ctrl+C в его окне и старый бот, если он использует те же файлы. Закрытие страницы браузера сервер не останавливает. Запишите эффективные пути и счётчики документов/обращений/писем.
2. Сделайте приватную копию командой выше и отдельную защищённую копию `.env`. Не удаляйте старую папку.
3. Распакуйте новый ZIP **в отдельную временную папку**, не поверх работающего приложения. У общего программного архива нет `.env`, рабочей БД и закрытых PDF. Для обычного обновления скопируйте из распакованного `posteks_ai` код, `frontend`, `migrations`, `scripts`, шаблоны и инструкции в существующую папку программы с заменой программных файлов. Не удаляйте прежнюю папку и не заменяйте/очищайте `.env`, `storage`, `.venv`, `backups`, собственные внешние каталоги документов и рабочую БД. Существующий `.env` оставьте, недостающие новые имена переносите из `.env.example` по одному. Не принимайте пустую новую установку за потерю старых данных.
4. Если сознательно меняете папку установки, для переноса уже работающей **этой схемы** перенесите согласованный snapshot БД и `storage` в свою постоянную папку данных. Укажите абсолютные пути в сохранённом `.env`; например `DATABASE_URL=sqlite:///C:/POSTEKS/data/posteks_ai.db`. При обновлении в прежней папке перенос данных не нужен. Не меняйте пароль/ключи и не подменяйте `.env.example` своими секретами. Для неизвестного старого `posteks.db` используйте раздел 7, а не прямую замену новой SQLite.
5. Запустите `install.bat`: перед миграциями создаётся ещё одна приватная копия существующих данных. Обновление применяет в том числе миграцию `f3b5c7d9e012`, добавляющую разрешение на использование документов в ответах. Существующие файлы, права на оригиналы и переписка сохраняются; новое разрешение не включается автоматически. В Git checkout frontend пересобирается; у готового ZIP используется его свежая сборка. Для ручной пересборки — `install.ps1 -RebuildFrontend`.
6. Запустите `start.bat`, затем `open-app.bat`. Сравните пути/счётчики, откройте прежний диалог и PDF. Разрешите клиентские ответы по выбранным допустимым руководствам, оставив оригиналы внутренними. Запустите новое задание истории за 365 дней и проверьте ошибки и отсутствие дубликатов. Проверьте смену технического вопроса на счёт и отказ от посторонней задачи. Не подтверждайте обновление лишь по открывшейся главной странице.
7. Для отката остановите сервис, сохраните отдельную копию новых записей, затем восстановите **согласованную пару** прежнего кода и снимка БД/storage. Не смешивайте старый код с новой схемой и не удаляйте новую копию. Записи, созданные после старого snapshot, требуют отдельного сохранения/переноса.

Сборка передаваемого программного архива: `python -m scripts.export_project --output <локальный путь.zip>`. Она включает код, готовый frontend и инструкции, проверяет CRC/признаки секретов, исключает `.env`, БД, storage, письма и закрытые документы. Это локальный файл для скачивания; команда ничего не отправляет в GitHub и не публикует приложение.
